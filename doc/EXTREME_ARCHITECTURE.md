# 全一_Extreme（UnifyIME_Extreme）核心架構與雙重校驗技術報告

全一_Extreme 是基於現代狀態機與注音容錯架構深度演化的最高階版本，專注於解決**「注音亂序自動正規化」**可能引發的誤校正問題，並實作**「極限冷啟動防爭用與按需載入（Zero-Contention Non-Blocking Startup）」**。

---

## 一、核心強化：音韻合法性與詞庫雙重校驗（Dual Evidence Verification）

### 1. 問題背景
在「全一_Super」中引入了注音亂序自動重排（如先打介音 `ㄧ` 再打聲母 `ㄐ`，自動重排為 `ㄐㄧ`）。然而，若僅依照分類位階（聲母 -> 介音 -> 韻母 -> 聲調）無條件重新排序，會面臨以下致命問題：
- **非法音韻拼合（Phonotactically Invalid Syllables）**：
  例如使用者輸入 `ㄦ` 後接 `ㄅ`，單純按 rank 重排會變成 `ㄅㄦ`；或是輸入 `ㄚ` 後接 `ㄐ`，重排成 `ㄐㄚ`。但國語注音中「兒韻不能帶聲母」，「舌面音 ㄐ/ㄑ/ㄒ 必須接 ㄧ 或 ㄩ」，這些非法組合在音韻學上根本不成立。
- **無詞庫證據的無效字詞**：
  若重排後雖然拼法符合某種規律，但在中文辭典中查無任何字詞，這往往表示使用者並非打錯順序，而是打出特殊縮寫或有其他輸入意圖，胡亂猜測反而破壞體驗。

### 2. 雙重校驗架構設計

```
使用者輸入符號（例如 incoming 嘗試併入 current）
          │
          ▼
   【模擬重排 Canonicalize】
          │
          ▼
   【第一重：音韻學合法性檢驗 (Phonotactics)】
    - ㄦ 韻不可帶聲母 / 介音
    - 舌面音 (ㄐ, ㄑ, ㄒ) 必須具備 ㄧ 或 ㄩ 介音
    - 翹舌/平舌音 (ㄓ, ㄗ 等) 嚴禁搭配 ㄩ 或 ㄧ
    - 舌根音 (ㄍ, ㄎ, ㄏ) 嚴禁搭配 ㄧ 或 ㄩ
    - 唇音 (ㄅ, ㄆ, ㄇ, ㄈ) 嚴禁搭配 ㄩ，ㄈ 嚴禁搭配 ㄧ
    - 介音與韻母搭配相容表嚴格限制
          │
          ├─► 不合法 ──► 【拒絕合併 / 拒絕重排，保留原樣】
          │
          ▼ 合法
   【第二重：詞庫存在性證據檢驗 (Lexicon Evidence)】
    - 呼叫 `LexiconStore.hasEvidence(forSyllable:)`
    - 檢查自身或四聲/輕聲變體在 common / phrase / override 中是否存在候選字
          │
          ├─► 無證據 ──► 【拒絕合併 / 拒絕重排，保留原樣】
          │
          ▼ 有證據
   【採納正規化結果】──► 順暢組字並精準命中候選字！
```

## 二、極限冷啟動防爭用（Zero-Contention Non-Blocking Startup）

### 1. 痛點剖析
在傳統輸入法啟動時：
- 主執行緒與多個背景任務同時爭用同一把鎖（Lock Contention）。
- 中文、7MB 英文詞庫、CoreML 神經網路模型同時初始化，造成 CPU 暴衝、I/O 阻塞，導致使用者按下第 1 個鍵時出現頓挫。

### 2. Extreme 解決架構
1. **無鎖冷啟動預熱**：
   - 啟動時僅透過 `DispatchQueue.global(qos: .utility)` 在背景極低優先順序預熱中文核心詞庫與統計結構，不佔用高優先度 CPU。
2. **CoreML 與英文辭典真正按需載入（On-Demand Lazy Loading）**：
   - 啟動程序中徹底移除 `candidateRanker.isModelLoaded` 與 `EnglishIMEEngine` 的同步/非同步強載。
   - 只有在使用者真正觸發英文輸入、或候選字列表觸發 CoreML 重排時才進行載入。
3. **主執行緒第 1 鍵絕對流暢（Zero 1st-Key Latency）**：
   - 使用者一開啟輸入法敲下第一個鍵，輸入法主線程零鎖爭用、零 I/O 爭奪，達成真正的即刻秒響應。
